# AGENTS.md — правила работы над herd-ru

Инструкции для ИИ-агентов и контрибьюторов, которые правят сам патчер, словарь или
тесты. Пользовательская документация (установка, команды, откат) — в [README.md](README.md).

Проект: неофициальный перевод Laravel Herd (Windows) на русский. `patch.js` заменяет
строковые литералы в минифицированных чанках рендерера по словарю `dict/ru.json`,
подменяет `<title>` в HTML-окнах, ставит рантайм-шим для строк главного процесса
и пересобирает `app.asar`.

## Языки и стиль

| Что | Язык |
|---|---|
| Названия тестов (`test('english description')`) | **английский**, как в существующих файлах |
| Комментарии в коде и тестах, логи патчера, сообщения об ошибках | русский |
| README, AGENTS.md, `_readme`/`_note` в словаре | русский |
| Сообщения коммитов | английский, как в истории (`Add support of Herd 2.0.2`) |

- Форматирование и линт: Biome (`npx biome check .`), 2 пробела, одинарные кавычки,
  ширина строки 100; JS-файлы и `biome.json` — LF (см. `.gitattributes`).
- Перед сдачей работы: `npm test` и `npx biome check .` должны быть чистыми.
- Коммиты и пуши — только по явной просьбе.
- Не коммить генерируемое: `work/`, `build/`, `backup/`, отчёты в `patches/`
  (список в `.gitignore`). `patches/unpacked-files.txt` — эталон, он в репозитории.

## Пайплайн

`npm run patch` = `extract → apply → pack → install → launch`. Локальная проверка без
установки — `npm run extract && npm run apply && npm run pack` либо `npm test`
(тесты автономны и Herd не требуют). Локальная сборка и анализ не управляют
установленным Herd: изменения попадут в приложение только после `install`.

Команды и их ключи:

| Команда | Особенности |
|---|---|
| `extract` | Сначала сверяет бэкап, потом распаковывает `work/app` |
| `apply` | Словарь + HTML-заголовки + `valueFixes` + шим; пишет `patches/apply-report.json` |
| `pack` | `build/app.asar`; сверяет unpacked-состав с `patches/unpacked-files.txt` (210 файлов) |
| `install` | Закрывает Herd, копирует сборку (при необходимости через UAC), сверяет SHA256 |
| `backup` | Снимок оригинала; `--force` — снять копию даже с пропатченного архива |
| `restore` | Возвращает версию из бэкапа; при смене версии требует `--force` |
| `status` | Версии Herd/бэкапа/сборки, хэши, определение «наша сборка» |

### Что проверять после `apply`

`patches/apply-report.json`: `totalReplacements`, `changedJsFiles`, `htmlTitles`,
`replacedKeys` и `unusedKeys`. Для Herd 2.0.4 эталон: 1364 замены в 25 чанках,
11 заголовков, `unusedKeys` = только `["Downloading PHP ", "Local"]` (строки главного
процесса, требуют ручного решения).

`unusedKeys` имеет смысл **только на свежей распаковке**. После повторного `apply` по
уже пропатченному дереву английские оригиналы не находятся, и отчёт показывает почти
все ключи как неиспользованные. Поэтому `extract` и выбирает исходник осознанно
(`pickExtractSource`): если в Program Files лежит наша сборка, распаковка идёт из
оригинала в `backup/app.asar.orig` той же версии.

## Словарь

Секции `dict/ru.json`: `translations` (чанки рендерера), `htmlTitles`, `mainProcess`
(шим), `valueFixes`, `skipChunks`.

### Как работает замена (AST, Acorn)

- Совпадение **точное**, крайние пробелы сохраняются. Unpadded-ключ покрывает и
  паддинговый литерал через trim-fallback; обратное неверно — паддинговые ключи
  из 1.x не ловят текст без пробелов (на этом однажды потерялся перевод сообщения
  онбординга). Паддинговые двойники — кандидаты на удаление.
- Не переводятся (это код): ключи объектов, имена свойств, `import`/`export`,
  операнды `===`/`!==`/`==`/`!=`, выражения `case`. Именно поэтому запись словаря не
  может «починить» сравнение — если переводится значение, которое с чем-то
  сравнивается, используйте `valueFixes`.
- Template-литералы: переводятся статические квази-сегменты; «голый» идентификатор,
  склеенный с интерполяцией (`` `${mod}Key` ``), не трогается. `skipBefore` на квази
  не действует — только на обычные литералы.
- `createStaticVNode(...)`: переводятся только текстовые узлы между тегами, атрибуты
  не меняются.
- `files` — маски имён чанков (`settings-*`, массив), `paddedOnly` — только текст с
  крайними пробелами, `skipChunks` — дополнительно исключаемые чанки (базовые
  вендорные уже отсеиваются: `runtime-dom*`, `vue-router*`, `sentry*` и др.).
- После замен `apply` парсит каждый изменённый чанк повторно и при ошибке синтаксиса
  файл не записывает (в логе — `синтаксическая ошибка в <чанк> после замены — файл
  откачен`).

### valueFixes

Обычные записи — разовые исправления уже переведённого текста; в файле есть и
**постоянные** правки кода (подсказка MCP, карты OpenCode, вкладки «Диагностики»).
Правила:

- фикс должен быть идемпотентным: `to` не содержит `from`;
- `apply` применяет `from`→`to` простой заменой по каждому чанку и откатывает файл,
  если после замены он не парсится;
- если фикс перестал срабатывать, в логе будет `valueFixes применены в 0 файлах`,
  а в интерфейсе вернётся английский текст или логика (см. ниже);
- добавили фикс — поправьте связанную запись в `translations` и наоборот.

### mainProcess (шим)

`apply` кладёт в `work/app/out/main` файлы `ru-shim.js` и `ru-main-dict.json`; шим
перехватывает Electron API до загрузки байткода: `Menu.buildFromTemplate` (label,
tooltip), `dialog.showMessageBox*` (title, message, detail, checkboxLabel, buttons),
`Notification`, `BrowserWindow` (title, `setTitle`), `ipcMain.handle` (deepTranslate
ответа), `ipcMain.on` (`event.returnValue`), `webContents.send` и
`executeJavaScript` (замена длинных словарных строк в инжектируемом коде).

Ограничения и риски:

- Сам байткод (`index.jsc`) не меняется: строки, которые не проходят через
  перехваченные API (логи, консоль, часть CLI-сообщений), остаются английскими.
- `exact` срабатывает только на полное совпадение, `rules` — регэкспы для
  составных строк (пример: `^(.+) Logs$`).
- `deepTranslate` проходит по данным IPC в рендерер. Не добавляйте в `exact`
  короткие generic-слова (`Failed`, `Local`, `Site`, `Message`) — они могут
  оказаться значениями полей и сломать сравнения в интерфейсе. Для строк главного
  процесса сначала убедитесь, где они показываются.
- Журнал шима: `%APPDATA%\Herd\ru-shim.log` (типы `menu`, `dialog`, `notification`,
  `deep`, `ipc`, `send`, `exec`). По нему видно, что реально приходит в API.

## Правила перевода

- Не переводить: ключи логики, значения enum/`case`, payload-имена
  (`Dump`, `Query`, `Request`, `Response`, `Job`, `Log`, `View`), имена сервисов
  (`Mail`, `Dumps`), CSS-классы, SVG-пути, иконки-лигатуры (`Next`, `Previous`),
  имена продуктов и команд (`Adminer`, `Tinkerwell`, `Herd`, `dump()`).
- `Ungrouped` — идентификатор, обычной заменой строк не переводится.
- Если подпись элемента и ключ логики — одна строка, переводится только отображение.
  Пример: окно «Диагностика» (`dumps-*`) — подписи вкладок берутся из
  `DUMP_DISPLAY_KIND_TITLES`, а ключи фильтра `DUMP_DISPLAY_KIND_TAB_FILTERS`
  и ключ вкладки «Все» остаются английскими (иначе ломаются подсчёт, блокировка
  вкладок и `window.api.dumps.setColor`). Правки — в `valueFixes`, пояснение — в
  `_note` словаря.
- Фрагменты-связки (`" in "`, `" and "`, `" for "`) добавляйте только с `files` и
  только после проверки, что в этих чанках фрагмент встречается как переводимый
  ровно там, где нужно. Проверка контекста: `node patches/inspect-strings.js search "фраза" [чанк]`
  или разбор по AST (литералы + квази-сегменты с позициями).
- Строки библиотек внутри чанков (moment, lodash, highlight.js, iFrameResizer,
  Sentry) — не UI: не переводить, даже если они выглядят как текст.
- Пустых `translations`-записей быть не должно: на свежей распаковке `unusedKeys`
  должен содержать только осознанно оставленные исключения. Мусорные ключи вредны —
  они маскируют реальные пропуски (Herd переформулировал строку → перевод молча
  перестал применяться).

### Чистка словаря

`node patches/analyze-strings.js unused` раскладывает `unusedKeys` из
`patches/apply-report.json` по действиям (файлы: `patches/unused-keys.txt|.json`):
текст ещё в чанках (замена не применилась — проверьте позицию), расхождение по
краевым пробелам, строки главного процесса без шима, дубли уже покрытых шимом
и «мёртвые» ключи. Удалять можно только «мёртвые»; остальные — глазами.

При построчном удалении ключей правьте **исключительно секцию `translations`**:
`htmlTitles` и `mainProcess` содержат строки с теми же 4 пробелами отступа и
совпадающими ключами. После удаления проверяйте, что JSON валиден, остальные секции
не изменились, а число ключей совпало с планом.

### Известные открытые пункты

- `"Downloading PHP "` и `"Local"` — строки главного процесса, место показа не
  подтверждено; в `translations` оставлены намеренно.
- `backup/app.asar.orig.unpacked` (~700 МБ) устарел: `restore` возвращает только
  `app.asar`, распакованное дерево пересобирается при `pack`.

## Обновление Herd

Порядок для новой версии:

1. Установить обновление Herd (свежий оригинал появится в Program Files).
2. `npm run extract` — оригинал новой версии автоматически уйдёт в `backup\`, а
   `work/app` распакуется из него.
3. `npm run apply` — посмотреть отчёт: резкое падение `totalReplacements` или рост
   `unusedKeys` означает, что Herd переименовал чанки/строки; разбираться через
   `node patches/analyze-strings.js fresh|remaining|unused`.
4. `npm run pack` — сверить, что unpacked-файлов 210 и состав совпал с эталоном;
   при расхождении обновить `patches/unpacked-files.txt`.
5. `npm run install-patch && npm run launch` — установить и проверить интерфейс.

Проверка установленной сборки без глаз: прочитать строки прямо из
`C:\Program Files\Herd\resources\app.asar` (`asar.extractFile(..., path.join('out',
'renderer', 'assets', '<чанк>.js'))`) и убедиться, что нужные русские строки на месте.

## Бэкап, откат и аварийное восстановление

- Автоснимок делает `refreshOriginalBackup()` перед `extract` и `install`; он
  намеренно **не** снимает копию с пропатченного архива (иначе затрёт оригинал) и
  сверяет SHA256 до подмены файла. Результат фиксируется в `backup\INFO.txt`
  (версия, дата, алгоритм, хэш, источник, путь бэкапа) — формат читается и человеком.
  Обходить защиту — только осознанно, с `--force`.
- «Наша сборка» определяется по маркеру `out\main\ru-shim.js` внутри архива или по
  совпадению с `build/app.asar`. Путь записи собирается через `path.join`: asar-читалка
  делит имя по разделителю текущей платформы.
- `restore` предупреждает о даунгрейде (`restoreConflict`) и требует `--force`.
- Если чистый архив потерян, оригинал последней версии можно достать из кэша
  апдейтера: `%LOCALAPPDATA%\herd-updater\pending\Herd-<версия>-setup.exe` — это
  7z-архив, внутри `resources\app.asar`; подлинность проверяется сверкой sha512
  файла с `update-info.json` рядом. Совпадение содержимого с `work/app` проверяется
  побайтовой сверкой файлов, которые `apply` не менял.
- Herd может работать с правами администратора: обычный `taskkill` получает «Отказано
  в доступе». Поэтому elevated-скрипты `install`/`restore` первым делом делают
  `taskkill /F /IM Herd.exe`, иначе после установки останется работать старая сборка.
- Заголовок asar кешируется по пути: после подмены файла в том же процессе версия
  читается неверно, поэтому `herdVersionOf` сбрасывает кеш (`asar.uncache`).

## Тесты

`npm test` — встроенный `node:test`, фреймворк не нужен. Файлы:

| Файл | Что покрывает |
|---|---|
| `tests/translate.test.js` | Механика замен: литералы, пробелы, `files`, `skipBefore`, `paddedOnly`, template-сегменты, `createStaticVNode`, `skipChunks` |
| `tests/shim.test.js` | Шим главного процесса на подставных Electron API |
| `tests/pipeline.test.js` | `apply`/`pack` на фикстурах: отчёт, откат при ошибке синтаксиса, ASAR и unpacked |
| `tests/backup.test.js` | Снимок бэкапа, пропуск пропатченного архива, `--force`, выбор исходника `extract`, чтение версии |
| `tests/unused-keys.test.js` | Классификация `unusedKeys` |

Правила:

- Тесты полностью изолированы: работают только во временных каталогах
  (`os.tmpdir`), мокают `console`, не трогают установленный Herd, `work/`, `build/`,
  `backup/` и словарь проекта.
- **Всегда** проверяйте, что подставляемые пути лежат внутри временного каталога:
  однажды тест передал функции неверные имена параметров, та взяла реальные пути
  проекта и перезаписала `backup/app.asar.orig` пропатченным архивом.
- Для внедрения путей `patch.js` экспортирует `buildLookup`, `translateFile`,
  `cmdApply`, `cmdPack`, `herdVersionOf`, `isPatchedAsar`, `pickExtractSource`,
  `restoreConflict`, `refreshOriginalBackup`. CLI-диспетчер срабатывает только при
  `require.main === module`, поэтому импорт патчера ничего не выполняет.
- Новая функциональность = тест: чистые предикаты (`restoreConflict`,
  `classifyUnused`) тестируются напрямую, файловые операции — на временных архивах,
  собранных через `@electron/asar`.
- Названия тестов — английские, комментарии внутри — русские.

## Инструменты анализа (`patches/`)

Все режимы требуют `work/app` (сначала `extract`), кроме `filter`.

| Команда | Назначение |
|---|---|
| `node patches/analyze-strings.js candidates` | Английские UI-кандидаты: `candidates.json`, `candidates.txt`, `html-titles.txt` |
| `… filter` | Оставляет кандидаты из чанков приложения: `ui-candidates.txt` |
| `… fresh` | Кандидаты, отсутствующие в словаре (включая template-сегменты): `fresh-strings.txt` |
| `… remaining` | Широкий поиск оставшихся строк без CSS/URL/путей: `all-remaining.txt` |
| `… unused` | Разбор `unusedKeys` из отчёта `apply`: `unused-keys.txt`, `unused-keys.json` |
| `… all` | `candidates → filter → fresh → remaining → unused` |
| `node patches/inspect-strings.js search "фраза" [чанк]` | Контекст литерала по префиксу |
| `… find / fragments / contexts / check-fragments / check-final` | Наборы известных проверок контекста |
| `node patches/scan-bytecode.js` | Строки из `index.jsc` → `patches/main-menu-strings.txt` (использует общий модуль `patches/bytecode-strings.js`) |
| `node patches/verify-shim.js` | Проверка шима и словаря в собранном архиве |

Проверки `inspect-strings.js` находят чанки независимо от hash в имени, а отсутствие
обязательного чанка завершают с ненулевым кодом — их можно использовать как быстрый
регресс-тест после обновления Herd.

Отчёты анализатора генерируемые (см. `.gitignore`). Анализатор — обычный скрипт;
при добавлении режима держите `require.main === module` на диспетчере, чтобы функции
можно было импортировать в тестах. Тесты в CI запускает
`.github/workflows/tests.yml` (pull request → `npm test`).
