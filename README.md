# Herd RU — русская локализация Laravel Herd (Windows)

Неофициальная локализация интерфейса [Laravel Herd](https://herd.laravel.com) для Windows на русский язык.
Работает поверх установленного Herd, ничего в самой системе Herd (PHP, NGINX, сайты) не меняет.

</p>

**Принцип:** патчер распаковывает `app.asar`, точечно заменяет английские
строковые литералы в минифицированных чанках интерфейса по словарю `dict/ru.json`,
пересобирает архив и устанавливает его обратно. Словарь строится на точных совпадениях
«английская строка → русская строка», поэтому патчер идемпотентен и переживает
обновления Herd: после апдейта достаточно повторить `extract → apply → pack → install`.

## Что переводится

- Все окна интерфейса: Settings (Общие, Сайты, Сервисы, PHP, Интеграции, Горячие клавиши, Лицензия, О программе), Site Wizard, Dumps, Mails, Logs, Log Viewer, Link Remote Site, Onboarding, Updater, меню трея (menubar)
- Заголовки окон (`<title>`)
- Кнопки, тултипы, плейсхолдеры, сообщения об ошибках, таблицы

**Не переводится (намеренно):**

- Строки главного процесса, скомпилированные в V8-байткод (`out/main/index.jsc`): редкие нативные диалоги, уведомления Windows, тексты ошибок лицензии — они не поддаются текстовой замене
- Имена сервисов и ключи сравнения в коде (`Mail`, `Dumps`, `NGINX`, payload-имена `Query`/`Request`/`Response`/`Dump`/`View`/`Job`/`Log`), названия фильтров окна Dumps — их замена ломала бы логику
- Имена продуктов (Herd Pro, Expose, Forge, Tinker, Adminer), названия фреймворков, команды (`php artisan tinker`), имена иконок-лигатур (`Next`/`Previous` в шрифте Segoe Fluent Icons)

## Требования

- Windows, установленный Laravel Herd (проверено на 1.30.0)
- Node.js 22.12 или новее — старейшая поддерживаемая линия LTS (проверено на 24.x;
  минимум обусловлен зависимостью @electron/asar). Зависимости ставятся автоматически:
  `npm install`

## Структура проекта

```
<папка проекта>\
├── patch.js              # патчер (все команды)
├── dict\ru.json          # словарь перевода: translations (JS) + htmlTitles (заголовки окон)
├── backup\app.asar.orig  # ОРИГИНАЛЬНЫЙ app.asar на момент первого патчирования (+ INFO.txt, SHA256)
├── work\app\             # распакованное приложение (здесь правятся файлы)
├── build\app.asar(+.unpacked)  # собранный патченный архив
├── patches\              # скрипты анализа и эталонный unpacked-files.txt; отчёты замен
│                         # и извлечённые списки строк генерируются заново (см. .gitignore)
├── .gitignore            # бинарники Herd (backup/build/work) и генерируемые артефакты
│                         # не попадают в репозиторий — коммитятся только словарь, скрипты и README
└── README.md
```

## Команды

Выполнять в папке проекта. Первый раз — `npm install`. Все пути скрипты определяют
от собственного расположения, поэтому проект можно свободно переименовать или
перенести на другой диск, а команды — запускать из любого каталога.

| Команда | Что делает |
|---|---|
| `node patch.js status` | Текущее состояние: что установлено (оригинал/патч/новая версия), хэши |
| `node patch.js extract` | Распаковать установленный `app.asar` в `work\app` |
| `node patch.js apply` | Применить словарь к `work\app` (+ проверка синтаксиса каждого чанка) |
| `node patch.js pack` | Собрать `build\app.asar` + `app.asar.unpacked` |
| `node patch.js install` | Установить сборку в `C:\Program Files\Herd` (закрывает Herd; без прав администратора запросит UAC; результат подтверждается сверкой SHA256) |
| `node patch.js restore` | Вернуть оригинальный `app.asar` из бэкапа (UAC) |
| `node patch.js launch` | Запустить Herd |

Те же команды доступны как npm-скрипты: `npm run extract`, `npm run apply`,
`npm run pack`, `npm run install-patch`, `npm run restore`, `npm run status`,
`npm run launch`. Полный цикл целиком — `npm run patch`. Установка названа
`install-patch` (не `install`), потому что скрипт с именем `install` npm
выполняет автоматически при каждом `npm install` — патчер бы запускался при
просто установке зависимостей.

Полный цикл патчирования:

```bat
cd /d <папка проекта>
npm install
node patch.js extract
node patch.js apply
node patch.js pack
node patch.js install
node patch.js launch
```

Восстановление оригинального Herd:

```bat
node patch.js restore
```

## Как добавить/поправить перевод

1. Откройте `dict\ru.json`. Формат записи в `translations`:

   ```json
   "Add Site": "Добавить сайт",
   "Failed": { "ru": "Сбой", "files": ["settings-*"] },
   "General": { "ru": "Общие", "skipBefore": "openSettings(" },
   "Next": { "ru": "Далее", "paddedOnly": true }
   ```

   - Значение-строка заменяется во всех JS-чанках; `files` — шаблоны имён файлов.
   - `skipBefore` — не заменять, если перед литералом стоит указанный код
     (защита мест, где та же строка является ключом логики, как `openSettings("General")`).
   - `paddedOnly` — заменять только вариант с пробелами по краям (например `" Next "` —
     кнопка в мастере сайтов), не трогая литерал без пробелов (`"Next"` — иконка-лигатура в Log Viewer).
   - Ключ сопоставляется с литералом точно; для текстовых узлов с пробелами по краям
     (« padded ») совпадение ищется по обрезанному значению с сохранением отступов.
   - Статические части template-литералов (`` `текст ${x}` ``) тоже переводятся.

2. Заголовки окон — секция `htmlTitles` (заменяет `<title>` в HTML окон).

3. Меню трея, нативные диалоги и уведомления — секция `mainProcess`
   (`exact` — точные строки, `rules` — регэкспы вида `" Logs$" → " Логи"`).
   Эти строки живут в V8-байткоде, их переводит рантайм-шим `out/main/ru-shim.js`,
   который патчер устанавливает при `apply` (перехват `Menu.buildFromTemplate`,
   `dialog.showMessageBox*`, `Notification` до загрузки байткода).
   Все строки, прошедшие через шим, пишутся в `%APPDATA%\Herd\ru-shim.log` —
   по нему удобно находить ещё непереведённые пункты меню.

4. Исправления уже переведённых значений (грамматика, согласование) — секция
   `valueFixes`: `{ "from": "старый перевод", "to": "новый перевод" }`. Нужна потому,
   что повторный `apply` не видит уже переведённые строки — оригинал-то заменён.

5. Поиск английской строки: `patches\candidates.txt` (все литералы с числом вхождений),
   `node patches\find-string.js "фраза"` (контекст в коде), `patches\all-remaining.txt`
   (всё оставшееся непереведённым после последнего прохода).

6. После правки словаря повторите `apply → pack → install`.

### Что нельзя добавлять в словарь

- Короткие слова, совпадающие с ключами логики: имена сервисов (`"Mail"`, `"Dumps"`
  внутри массива `defaultServices` и сравнений `arg.name`), payload-имена дампов
  (`"Query"`, `"Dump"`, `"View"`, …), значения `case`/enum, имя группы `"Favorites"`,
  аргументы `openSettings("General")` (для таких мест используйте `skipBefore`)
- Текст иконок-лигатур (spans с классом `font-icon`: `"Next"`, `"Previous"`, …) —
  вместо иконки появится текст; если слово нужно как кнопка — используйте `paddedOnly`
- CSS-классы (Tailwind) и SVG-пути — фильтр патчера их пропускает, но не добавляйте их в словарь
- `"Ungrouped"` (группа сайтов в списке) — доступается в коде как идентификатор
  `.Ungrouped`, а не строка, поэтому непереводима без правки байткода

Проверка контекста строки: `node patches\check-contexts.js` или `node patches\find-string.js`.

## После обновления Herd

Обновление перезаписывает `app.asar` — патч пропадает (это нормально и безопасно).
Чтобы вернуть русский язык:

```bat
node patch.js extract    :: распакует НОВУЮ версию
node patch.js apply      :: словарь найдёт знакомые строки; непереведённое останется английским
node patch.js pack
node patch.js install
```

Новые строки, добавленные Beyond Code в новых версиях, появятся в отчёте
`patches\apply-report.json` как непереведённые — добавьте их в словарь.

## Технические детали

- Herd — Electron-приложение (Vue 3 + Vite). Интерфейс — `out/renderer/assets/*.js`
  внутри `app.asar`; строки зашиты в минифицированный код без i18n-фреймворка
- Проверка целостности asar у Herd отключена (Electron fuse
  `EnableEmbeddedAsarIntegrityValidation = 0`), поэтому замена архива безопасна
- Файлы `resources/bin|config|valet/**` и `resources/*.png` выносятся из asar
  (unpacked), как в оригинальной сборке — иначе Herd не сможет запускать php/phar/nginx.
  Эталонный состав — `patches\unpacked-files.txt`; `pack` ждёт ровно 180 unpacked-файлов,
  как в оригинале, и предупреждает при отклонении
- Главный процесс и preload — V8-байткод (bytenode). Для его видимых строк
  (меню трея, диалоги, уведомления, заголовки окон логов) патчер ставит рантайм-шим
  `ru-shim.js`, перехватывающий Electron API до загрузки байткода; его журнал —
  `%APPDATA%\Herd\ru-shim.log`
- Каждый изменённый чанк проходит синтаксический разбор (acorn) до записи;
  при ошибке файл откатывается
- Отчёт после apply: `patches\apply-report.json` — все замены. Список «неиспользованных»
  ключей осмыслен только для первого apply на свежей распаковке: при повторных прогонах
  ключи прошлых раундов всегда «неиспользованы», потому что оригиналы уже заменены

## Откат и гарантии

- Оригинальный `app.asar` лежит в `backup\app.asar.orig` (SHA256 в `backup\INFO.txt`).
  `node patch.js restore` возвращает его за один шаг
- Патч не трогает: `Herd.exe`, `HerdHelper.exe`, PHP/NGINX/драйверы, файлы сайтов,
  конфигурацию (`%APPDATA%\Herd`), hosts
- Обновления Herd продолжают работать штатно (патч просто затирается, см. выше)

## Лицензия и статус

Herd — проприетарный продукт Beyond Code. Код патчера и словарь перевода
распространяются под лицензией **MIT** (файл `LICENSE`); распространять
патченный `app.asar` по-прежнему нельзя — бинарники Herd в репозиторий не
входят. Для работы патчера нужен легально установленный Herd. Не является
официальной локализацией; авторы Herd к ней отношения не имеют.
